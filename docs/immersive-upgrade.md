# CultureLoop immersive upgrade — implemented 11 October 2026

The approved additional scope is implemented in the existing six-screen app. The React application remains canonical; the completed Spotify/DICE Mobbin research and editable Figma directions were reused rather than starting another product/design exploration. No new client dependencies, authentication, database schema or Neon production changes were required.

## Delivered experience

- **A moving universe:** staged formation, bounded silent node drift, rotating memory/orbital rings and travelling highlights on real connections. Meshes, lines and labels share the same positions. Camera navigation, guided preview handoff, hover/selection, touch, pause, reduced motion and WebGL recovery remain functional. Hidden/offscreen animation suspends; no random particle cloud or expensive bloom layer was added.
- **Three choices from twenty:** 13 distinct source-supported additions preserve the original seven. The deterministic ranking weights are unchanged. Eligible-pool ranking and displayed selection are separated, with quality gates for discovery/diversity. Six contrasting profile fixtures produce at least five different initial three-event sets. Similar users can share recommendations; no randomness or uniqueness guarantee is implied. Short filtered pools are not padded.
- **Controlled exploration:** Try another connection swaps one active chapter, preserves the other two and remembers skipped IDs for this exploration. Both views use the same IDs; constellation and list remain exclusive. No available alternative produces an explicit disabled state.
- **Cultural meaning:** a manual memory → matched taste → actual event tour and a three-step relationship strip accompany approved programme notes. Three featured previews have authored questions; other previews offer an honest form-based question. Notes are editorial invitations supported by the linked programme, not claims of historical lineage or organiser endorsement.
- **Music continuity:** the onboarding taste mix remains central, with neutral ambient fallback. A new sound uses supported music tags of the selected event and smoothly releases the previous mix while retaining the same running audio context. Original synthesis is user-started, controllable and clearly labelled; saving/AI/animation never autoplays it.
- **A collection with intent:** optional reason chips and a 280-character note persist per saved event, with backward-compatible validation. Reload and new exploration preserve notes/saves/balance. Saved orbit markers and the journey line reinforce continuity. Saving does not deduct credits or invent attendance.
- **Optional AI memory:** explicit short-input interpretation proposes supported taste/highlight enums with quoted evidence. Users edit/remove/accept suggestions; existing choices are preserved within the five-taste/two-highlight caps. Unsupported evidence, obvious negated evidence, stale replies and provider failures do not change manual choices. Schema validation cannot establish every semantic nuance; user review remains necessary.
- **Optional personal connection:** after accepted memory, an explicit event action asks AI to select approved cultural-note IDs. The server assembles exact trusted notes; practical event facts/rankings never come from generated prose. Results are cached in memory for this event/summary/taste set, capped at 30 and cleared for a new exploration/reset; they are not stored as a raw memory history.

## Actual engineering evidence

The full domain suite passes **40/40** tests. **16/16** server mock checks and **38/38** Chrome browser tests pass. Coverage includes all existing behaviour, silent motion/pause, guided opening, real touch drag/tap/scroll, differing profile maps, one-event swap, saved intent, AI acceptance/staleness/fallback and session narration cache. A full-suite mobile failure revealed Chrome omitting click after a canvas drag; stationary primary touch-up now activates event controls while scrolling/cancellation does not select. Mouse and keyboard retain native clicks. Compiled visual inspection exposed a stationary pointer holding a forming node near the core; holds now wait for formation/easing, and a new remount regression verifies it. The final compiled mobile/desktop scenes were inspected after this correction.

Production TypeScript/Vite build passes. Compiled desktop/mobile smoke checks pass for actual WebGL, exclusive views, preview audio, save/reload, assets and overflow. Marker scans and comparison with actual private environment values found no credential values in client JS. The local production-preview API rejects empty input with HTTP400 without calling the provider.

The four-size spatial check measured **59.2–60.2 render callbacks/sec** over roughly five seconds on this headless Chrome host, with zero additional idle frames while paused and stable positions. This does not certify physical GPU presentation or phone performance. Compiled active-scene main-thread work measured 723ms over four seconds in the final check (earlier samples ranged from 560–779ms); earlier 1ms idle figures describe the superseded static/on-demand scene. The lazy 3D module remains about 260 KB gzip with Vite's size advisory.

One explicit real OpenAI interpretation returned HTTP200 in 2364ms, using `gpt-4o-mini-2024-07-18`, 279 input +55 output =334 tokens. Other AI automated checks are mocks; no latency/reliability guarantee follows from one example. Audio signal/control state is tested; subjective physical-speaker listening, Safari/device testing, participant trials and formal screen-reader certification remain unclaimed.
